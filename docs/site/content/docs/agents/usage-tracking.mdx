---
title: Usage & rate-limit tracking
---

Orca tracks usage for Claude Code, Codex, Muse Code, Gemini, OpenCode, Kimi Code, and MiniMax and surfaces it in the status bar, so you know how close you are to a rate limit before an agent stalls.

## What's shown

- Current usage against the active account's plan.
- Time to reset for 5-hour, daily, weekly, and Claude Fable weekly windows (where applicable).
- A warning chip when you cross 80% of a limit.

## How it works

The source depends on the provider. Orca reads local usage state where available (under `~/.claude`, `~/.codex`, and the Gemini/OpenCode equivalents), or asks the provider's CLI for its current allowance. Readouts reflect the latest available provider snapshot.

### Muse Code

When the `muse` CLI is detected, the **Muse Usage** status-bar item shows its subscription session and weekly windows, including reset times. Toggle it under **Settings → Appearance** or the status-bar menu.

Orca runs `muse usage --json` with automatic updates disabled. [Muse Code 1.4.13 introduced this command](https://dev.meta.ai/docs/muse-code/changelog); it may contact Meta to refresh the allowance and does not start a model turn. Muse owns authentication: sign in with `muse login` on the host running your agents. Orca does not copy Muse credentials into its settings. Older CLI versions without the `usage` command show update guidance.

If Meta returns no allowance, the meter shows **Usage unavailable**. Missing allowance is not zero usage or a full quota, and Orca does not spend a model request to obtain a reading. Muse's historical token totals in Stats are separate from subscription quota.

For a remote workspace, usage belongs to its execution host. An older host that does not report Muse usage cannot supply a meter; the viewer's local Muse allowance is not substituted.

## Multi-account accounting

The status bar always reflects the _active_ account. Other configured accounts are visible in the account switcher with their own usage.

## Usage roster

Click the usage segment in the status bar to open the **Usage** popover. It lists every tracked provider (icon · name · plan · soonest reset · per-window bars), sorted so the tightest limit is first. Use the header refresh control to re-read local usage state.

- **Detailed** — full bars, labels, and percentages for every window
- **Compact** — only the tightest window per provider

Under [Settings → Appearance](/docs/settings), choose **% used** vs **% remaining** for how those numbers read.

Rows without live numbers show a short status instead: **Loading usage…**, **not signed in**, **Usage unavailable**, **No usage data**, or a provider-specific error. Claude and Codex rows can drill into account switching; **Manage accounts** opens Settings.

### Mobile

On the companion app, open the host **Accounts** screen for Claude and Codex account usage. The Muse quota meter is currently available in the desktop and web status bar. When Codex has earned **rate-limit reset** credits, spend one from that screen (see [Mobile companion](/docs/mobile)).

## Estimated cost (Stats)

The Stats breakdown may show **estimated cost** for known model families (including Claude 5-class and Codex GPT-5.6 rows). Rows marked **• inferred pricing** use Orca’s local price table, not a live bill from the provider. Prefer the provider console for authoritative spend.
